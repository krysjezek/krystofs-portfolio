# Header utility ? 24 September 2026

Source: homepage at `http://localhost:3000` and the owner's header screenshot. Designed first in the existing [Figma utility component](https://www.figma.com/design/z5qZnFX6vkOKlWrVKzdoFR?node-id=253-918), then implemented.

The final header is **Prague, local time, temperature**. Email/X controls and the proposed divider are removed. All three values use the existing **Portfolio / Body** style: Roobert PRO Regular 17.5/28 with -0.5% tracking. CSS shares the regular body-size tokens with the site name; compact page copy can retain its existing 16px style. Prague and temperature are secondary ink; time is primary ink. All three fields hug their text, with equal 12px gaps. Fixed-width numeric slots were removed because their trailing whitespace made the visible spacing uneven.

The supplied `C:/Users/kryst/Downloads/font/RoobertPRO-Regular.woff2` was compared with the served font using FontTools: all glyph outlines/advances, cmap, GSUB, GPOS, hmtx and names are identical. Only font header metadata differs. The mismatch was CSS `tabular-nums`; it has been removed. Figma and the browser now use default proportional numerals.

The linked utility propagates to desktop, tablet and mobile header modules. Mobile instance: `433:2851`. Below 360px, Prague sits above time and temperature to avoid shrinking the requested typography or overlapping the name. The 390px layout stays on one line.

Weather comes from [MET Norway Locationforecast](https://docs.api.met.no/doc/ForecastJSON.html), using fixed central Prague coordinates. `/api/weather` identifies the site to the provider, caches the upstream forecast for an hour, selects the nearest valid hour and returns rounded Celsius. Browser/shared response caches are 5/10 minutes. The client refreshes every 10 minutes while visible and on returning to the page. Requests time out after 8 seconds. Missing, malformed, stale-hour or failed responses show an em dash with an accessible unavailable label. The temperature text links to the provider's [source and CC BY 4.0 license](https://api.met.no/doc/License); its title identifies the hourly forecast and whole-degree rounding. No API key or visitor location is required.

Verification: Figma body-style linkage and renders checked; live endpoint returned a valid Prague temperature. Browser checks cover 320, 390, 599, 600, 834, 1440 and 1920px, 17.5px typography, default numeral features, no overflow/overlap, removed actions and weather failure. Weather tests cover nearest-hour selection, rounding, provider identification/cache settings and malformed/stale data/provider failures. Lint, build, portfolio, icons, tooltips, interactions and the 33-screen layout suite pass. Unrelated recognition changes remain separately owned.

## Revision — 29 September 2026

The 24 September specification above was implemented in `38d9fac`, then reverted piecemeal by `6eb2948` and `d7ddd14`. The utility had drifted to a 14/20 size that exists nowhere else in the scale, 4px gaps, fixed 39/40px numeric slots, `tabular-nums` on the clock only, and a two-row 104.5px header below 479px. `scripts/verify-header-utility.mjs` had been rewritten to assert that drift, and `scripts/verify-layout.mjs` carried a `+= 34` patch acknowledging the header no longer matched its own Figma fixture. This revision restores the intent and settles the two questions the original left open.

**Type.** The cluster uses **Portfolio / Body Compact — `--type-body-compact`, 16/24**, not the 17.5/28 body size specified on 24 September. 17.5/28 is correct about belonging to the system but wrong about emphasis: at that size the utility matches the wordmark in size, weight and — for the Prague trigger — colour, so the header loses its anchor. 16/24 is an existing named role, reads as one deliberate step below the wordmark on desktop, and equals page body copy on mobile, where `--body` is already 16/24.

**Colour carries the hierarchy, not size.** All three fields are `--muted`. The Prague trigger was previously `--ink`, identical to the wordmark; that single declaration, not the type size, was what made the utility shout when it was set at body size. The wordmark is now the only ink in the header.

**One numeral style.** `font-variant-numeric: tabular-nums` is declared once on `.prague-clock` and inherited by both values, replacing the previous split where the clock was tabular and the temperature proportional. The 24 September note removed `tabular-nums` to resolve a Figma/browser mismatch; reinstating it uniformly is what keeps the clock from reflowing its neighbours every minute, which is what tabular figures are for.

**Values hug; the anchored edge is what holds still.** The fixed 39/40px slots are gone, as originally specified. Because the cluster is right-anchored and the clock is last, a temperature crossing a digit count reflows only the items to its left; the right edge never moves. The suite asserts the right edge, not whole-cluster stability.

**Optical alignment.** The clock carries the same `--utility-pad` as the triggers and `.prague-clock` bleeds that padding back out with a negative margin, so the *text*, not the hover pill, aligns to `--inset`. Verified at 0.0px deviation at every width.

**One row, always.** The two-row mobile header is removed; the header is 70.5px at every width. Measured single-row slack between the wordmark and the cluster: 1031px at 1440, 131px at 480, 44px at 393, 26px at 375, 11px at 360. Below 360px the cluster drops the word "Prague" (`.airspace-trigger-label`) rather than stacking or shrinking; the plane glyph remains the trigger, giving 68px of slack at 359px and 29px at 320px. This restores the 24 September rule that the 390px layout stays on one line, and it removes the `+= 34` deviation from `verify-layout.mjs` — all 33 Figma screens and 423 coordinate checks now pass against the unmodified fixture, confirming the single-row header is what the design system specified all along.

**Figma is now behind the code.** The mobile header instance `433:2851` and Mobile Identity `23:237` still carry the two-row 104px treatment and the 14/20 type. They need re-syncing to match; until then, this document and `scripts/verify-header-utility.mjs` are the source of truth.

Verification: lint and production build pass. `verify-header-utility.mjs` passes at 1440, 834, 599, 480, 393, 375, 360, 344 and 320px, asserting single-row height, one type role and numeral style, the muted cluster with an ink wordmark, optical inset alignment, a stable right edge across 18/8/-12/31°C and the unavailable state, label reduction below 360px, 44px targets, order, touch and keyboard disclosure, and no horizontal overflow. `verify-layout`, `verify-portfolio`, `verify-context-previews`, `verify-tooltip` and `verify-media-loading` pass. `verify-footer`, `verify-icons` and `verify-interactions` fail on unmodified `HEAD` as well and are unrelated to this work.

## Masthead dateline — 29 September 2026

The utility is no longer a cluster of readings ranged against the wordmark. The header is now one masthead object: the name, and a dateline of live metadata. This replaced the 29 September revision above, which corrected the drifted cluster but kept its two-pole composition.

**Composition.** Above 600px the dateline ranges right over two rows — `PRAGUE  TUE 29 SEPT` over `20:18  18°C  PARTLY CLOUDY` — flush to `--inset`, giving the right side mass that answers the wordmark instead of a thin line trailing off the edge. Below 600px it stacks beneath the name as one left-aligned line and drops the date, the field a visitor already knows. The header holds **70.5px at every width**; measured slack at 320px is 107px.

**Type.** A new named role, `--type-micro` (400 10px/15px) with `--tracking-micro` (0.02em), uppercase, tabular figures, `--muted` throughout. The wordmark at 17.5/28 remains the only ink in the header. Buttons do not inherit `text-transform`, so both disclosures set it explicitly — without that, Prague and the condition render in sentence case beside an uppercase date.

**Condition, not count.** The third field was an aircraft count; it is now the weather condition. `briefWeather()` in `lib/weather.js` maps the provider symbol to a headline term of at most thirteen characters, because MET Norway emits phrases as long as "Heavy rain showers and thunder" — thirty characters, which overruns the 390px line. The full phrase is unchanged in the weather disclosure. When the symbol is unknown or the provider fails the field is dropped rather than rendered empty.

**Disclosures are words.** The plane and weather glyphs are gone; `Icon` is no longer imported by the header or `PragueAirspace`. The word **PRAGUE** is now the airspace trigger and the temperature/condition pair is the weather trigger, each darkening to `--ink` on hover. Both keep an expanded hit area via `::after`, taking no layout space.

**A bug the suite caught.** The first implementation expanded both hit areas symmetrically to 44px. Ranged right the two disclosures sit on adjacent 15px rows, so the weather target reached up over Prague and intercepted its pointer events — clicking the word would have opened the weather panel. Each target now expands *away* from the other: 35px inside the header when ranged right (comfortably past the 24px WCAG 2.5.8 minimum), and the full 44px when stacked on one line, where there is no neighbour above or below. `verify-header-utility.mjs` now hit-tests the rendered centre of Prague with `elementFromPoint` rather than trusting the geometry.

Verification: lint and production build pass. `verify-header-utility.mjs` passes at nine widths, asserting masthead height, one micro type role, the muted dateline with an ink wordmark, ranged-right above 600px and stacked below, a stable right edge across weather states, date reduction, non-overlapping targets, the Prague hit test, and no horizontal overflow; its scenario table now checks `briefWeather` across eleven provider symbols including the two longest. `verify-layout` passes all 33 Figma screens and 423 coordinate checks unchanged, confirming the header kept its height. `verify-portfolio`, `verify-context-previews`, `verify-tooltip` and `verify-analytics` pass. `verify-icons` header assertions pass and it then fails on a pre-existing `.contact-copy` email-icon timeout that also fails on unmodified `HEAD`; `verify-interactions` and `verify-footer` likewise fail identically on `HEAD` and are unrelated.

Figma remains behind the code: `12:154`, `23:236`, `23:237` and `587:1424` still carry the old cluster. This document is the source of truth until they are re-synced.
