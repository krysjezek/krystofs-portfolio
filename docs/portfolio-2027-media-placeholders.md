# Portfolio 2027 — media placeholders

Implemented 7 October 2026. Reserved media boxes paint an inline blurred
preview of their own artwork before the full-size poster arrives, so the
gallery never shows an empty grey rectangle.

## Problem

`Media` already reserved each box's dimensions and filled it with `--tag`
(#f5f5f5). That prevented layout shift but left a blank grey box until the
poster downloaded. A shimmer sweep was added first (see
[motion direction](portfolio-2027-motion.md) §01) and signalled "loading, not
broken", but it did nothing about time-to-pixels: the box stayed contentless.

## Decision

Each media record carries its own placeholder as a base64 `lqip` data URI,
handed to `next/image` as `blurDataURL` with `placeholder="blur"`. The
placeholder is inline, so it costs no request and paints with the HTML — it is
already on screen before the poster is requested, including for lazy artwork
below the fold.

Two alternatives were rejected. A separate `content/media-lqip.json` map looked
up at render time is cleaner separation, but `Home.jsx` is a client component
that imports its content directly, so the map would ship all 133 placeholders
to every page instead of the ~30 it renders. A build step merging a separate map
into records gets both properties at the cost of a codegen stage and a sync
obligation that is not earned at this size.

Baking generated bytes into authored files is the known cost of this choice. It
is contained because the files involved are render data, not provenance: the
`*-media.json` delivery records described in [video and media](video-and-media.md)
are not imported by the app and are never touched.

## Scope

`scripts/generate-lqip.mjs` rewrites only the content files the app imports and
renders through `Media`: `gallery.json`, `cases.json`, `pages.json`,
`profile.json` and `worlds.json`. 133 unique assets, 139 records.

Excluded, deliberately:

- **Icons, emoji and identity marks** (`icons.json`, `interface-icons.json`,
  `about-emojis.json`, `airlines.json`, and `card.icon`). They render at ≤64px
  and arrive in one packet; a blurred placeholder under them buys nothing.
- **Transparent artwork.** The generator probes each source with `ffprobe` and
  skips any alpha pixel format, because a blur fills the whole box and would
  paint a colour blob where the artwork is see-through. Three marks are skipped
  on this basis: `barbour.png`, `chainer-logo.png`, `yonex-logo-1.png`.
- **SVG**, which is already small and scales losslessly.

## Generator

`node scripts/generate-lqip.mjs` downloads each asset from Blob, downscales it
to a **32px-wide WebP** at `-q:v 30` with ffmpeg, and writes the base64 data URI
onto every record that references it. `--list` reports scope without writing;
`--print <path>` emits a single value.

It is idempotent: an unchanged source produces an identical string, so re-running
yields no diff. Before writing, it asserts each file round-trips through
`JSON.parse`/`stringify` unchanged, and aborts rather than reformatting a file
whose shape it would otherwise churn. Assets are fetched once however many
records share them, six at a time.

On Windows, Git Bash rewrites a leading-slash argument into a filesystem path;
`--print` needs `MSYS_NO_PATHCONV=1`.

32px was chosen against measurements: at 12px the preview is too vague to read
as the image, 20px captures the composition, and 32px is clearly better defined
while still costing **~216–264 bytes** against posters of 170–210KB. Cost on
disk: gallery.json +7.4KB, profile.json +3.9KB, cases.json +18.9KB,
pages.json +5.3KB, worlds.json +3.2KB. Only `gallery.json` and `profile.json`
reach the client bundle (~11KB), because `Home.jsx` is a client component; the
rest serialize per route and only for the records a page renders.

One media literal is hardcoded in `Worlds.jsx` rather than held in JSON. Its
`lqip` is inlined with a comment naming the `--print` command that regenerates it.

## Runtime

`Media` passes `placeholder={media.lqip ? "blur" : "empty"}` and
`blurDataURL={media.lqip}`. Next wraps the data URI in an SVG Gaussian-blur
filter as the `img` background and drops it when the poster paints. A record
without `lqip` degrades to the reserved grey box, unchanged.

The shimmer no longer applies to media: a recognisable blurred image already
says "loading, not broken", and sweeping over legible artwork would read as busy
against the quiet-surface direction. The `.shimmer` primitive stays in use by
the airspace panel, which has no artwork to preview.

Video is unaffected: the poster is still the first content, and video still
fades in over 360ms after `playing`.

## Verification

`node scripts/verify-media-loading.mjs` gates every `/_next/image` request and
asserts that all 32 homepage posters carry an inline placeholder, that no media
carries the shimmer class, and that the placeholder is handed off once the real
poster paints — at both motion preferences. Its pre-existing poster-first,
LCP-priority, deferred-video, scroll-playback and tall-frame assertions are
unchanged. `node scripts/verify-airspace-loading.mjs` continues to cover the
shimmer primitive.
